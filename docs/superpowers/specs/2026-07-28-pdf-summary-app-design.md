# PDF 요약 앱 — 설계 문서

- 작성일: 2026-07-28
- 상태: 사용자 승인 완료 (구현 계획 수립 대기)

## 한 줄 설명

PDF 문서를 업로드하면 AI(OpenRouter 무료 모델)가 핵심 내용을 요약해 보여주는, 로그인 없는 단일 페이지 웹 도구.

## 배경

- 형제 프로젝트([`../7장 공감 다이어리 앱 Study_05_01`](../../../../7장%20공감%20다이어리%20앱%20Study_05_01))의 스택·에이전트·`.env`를 재사용한다.
- 다만 이 앱은 형제 프로젝트와 달리 **로그인·DB 저장이 필요 없는 완전한 stateless 도구**다. `.env`는 형제 프로젝트와 동일한 파일을 재사용하지만, 실제로 이 앱이 쓰는 값은 `OPENROUTER_API_KEY` 하나뿐이다(`DATABASE_URL`, `AUTH_*`는 미사용).

## 범위

포함:
- PDF 업로드(드래그앤드롭 + 클릭 선택) → 서버에서 텍스트 추출 → OpenRouter 무료 모델로 요약 → 결과를 한 화면에 표시
- 한글 인터페이스, 반응형(모바일 포함)

제외(이번 범위 아님):
- 로그인/계정, 요약 히스토리 저장(DB)
- 스트리밍 요약 표시
- 긴 문서(20페이지/4MB 초과)에 대한 청킹(map-reduce) 처리 — 대신 명확한 제한 에러로 대응

## 아키텍처

- **프레임워크**: Next.js App Router, Vercel 배포 (형제 프로젝트와 동일 스택)
- **인증/DB 없음**: 완전한 stateless 도구. 업로드 → 처리 → 결과 표시가 한 번의 요청-응답으로 끝난다. 새로고침하면 결과는 유실된다(의도된 동작).
- **페이지 구조**: 단일 페이지(`/`)에서 상태 전환으로 전체 흐름을 표현
  - `idle`(업로드 대기) → `processing`(처리 중) → `result`(결과 표시) / `error`(에러 표시)
- **API**: `POST /api/summarize` 단일 엔드포인트 — PDF를 받아 검증 → 텍스트 추출 → 요약까지 한 번에 처리 후 결과 반환. 세션/상태 없음.

## 컴포넌트 구조

**프런트엔드** (`app/`, `components/`)
- `app/page.tsx` — 단일 페이지, 4가지 상태(idle/processing/result/error) 관리
- 드래그앤드롭 업로드 컴포넌트 (파일 선택 클릭으로도 대체 가능해야 함)
- 로딩 상태 컴포넌트 ("요약 생성 중...")
- 결과 표시 컴포넌트 — 한 줄 핵심 요약 + 주요 포인트 bullet 3~5개
- 에러 메시지 컴포넌트 — 원인별 한글 문구

**백엔드** (`app/api/`, `lib/`)
- `app/api/summarize/route.ts` — 업로드 수신 → 검증(형식/용량/페이지) → 추출 → 요약 → JSON 응답. `export const maxDuration = 60` 설정(형제 프로젝트와 동일 패턴).
- `lib/pdf/extract.ts` — PDF 텍스트 추출. 라이브러리는 `unpdf` 권장(Vercel 서버리스/Edge 친화적). 착수 시 backend-developer가 최신 문서 확인 후 최종 결정.
- `lib/ai/openrouter.ts` — OpenRouter 연동. 형제 프로젝트의 **무료 모델(`:free`) 순차 폴백 체인** 패턴을 재사용. 요약 프롬프트는 구조화된 JSON(한 줄 요약 + 포인트 리스트)을 요청하도록 설계.

**환경변수**
- `OPENROUTER_API_KEY` — 이 앱에서 실제로 사용하는 유일한 값. 현재 폴더의 `.env`(형제 프로젝트와 동일 파일)에서 로드.
- `DATABASE_URL`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_SECRET` — `.env`에는 존재하지만 이 앱에서는 사용하지 않음.

## 업로드 제한

- 최대 **4MB**, 최대 **20페이지**
- 클라이언트에서 1차 검증(UX용, 즉시 피드백)하지만 **서버가 최종 권위**를 가지고 재검증한다.

## 데이터 흐름

1. 사용자가 PDF를 드래그앤드롭하거나 클릭으로 선택한다.
2. 프런트엔드가 파일 형식(PDF 여부)·용량을 1차 검증한 뒤, `multipart/form-data`로 `/api/summarize`에 전송하고 즉시 `processing` 상태로 전환한다.
3. 백엔드가 형식·용량·페이지 수를 재검증한다. 통과하면 PDF에서 텍스트를 추출하고, OpenRouter 무료 모델에 요약을 요청한다.
4. 백엔드가 구조화된 요약(JSON: 한 줄 요약 + 포인트 리스트)을 응답한다.
5. 프런트엔드가 응답을 받아 `result` 상태로 전환하고 결과를 표시한다. 실패 시 `error` 상태로 전환하고 원인별 메시지를 보여준다.

## 에러 처리

| 상황 | 처리 |
|---|---|
| PDF가 아닌 파일 | 400, "PDF 파일만 업로드할 수 있습니다" |
| 4MB/20페이지 초과 | 400, "문서가 너무 큽니다(최대 4MB, 20페이지)" |
| 텍스트 추출 불가(스캔 이미지 PDF 등 텍스트 레이어 없음) | 400, "이 PDF에서 텍스트를 추출할 수 없습니다" |
| OpenRouter 무료 모델 실패/429 | 폴백 체인으로 순차 재시도 → 그래도 실패 시 502, "요약 생성에 실패했습니다. 잠시 후 다시 시도해주세요." |
| 처리 시간 초과(Vercel `maxDuration=60`) | 타임아웃 에러 메시지 표시 |

## 테스트 범위 (qa-engineer)

- 정상 경로: 일반 텍스트 PDF 업로드 → 구조화된 요약 성공적으로 표시
- 엣지케이스: 빈 PDF, 스캔 이미지(텍스트 없는) PDF, 페이지/용량 초과 PDF, PDF가 아닌 파일(.txt, .jpg 등), 한 문장짜리 초단문 PDF
- 무료 모델 레이트리밋/실패 상황에서 폴백 동작 확인
- UI: 드래그앤드롭 동작, 클릭 업로드 대체 경로, 로딩 상태, 에러 메시지 정확성, 결과 가독성(모바일 포함 반응형)
- 발견된 문제는 완전히 해결될 때까지 반복 수정한다(사용자 요청사항).

## 작업 분담 (사용자 지정)

1. **product-manager** — 이 설계를 바탕으로 상세 PRD·기능 명세 작성
2. **backend-developer** — PDF 업로드, 텍스트 추출 기능 구현
3. **ai-integration-specialist** — OpenRouter 연동, 추출 텍스트 요약 기능 구현 (무료 모델, `.env`의 `OPENROUTER_API_KEY` 사용)
4. **frontend-developer** — 드래그앤드롭 업로드 UI + 요약 결과를 깔끔하게 보여주는 한글 인터페이스 구현
5. **qa-engineer** — 다양한 상황에서 테스트, 문제 발견 시 완전히 해결될 때까지 수정
