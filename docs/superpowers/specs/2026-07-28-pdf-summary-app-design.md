# PDF 요약 앱 — 설계 문서

- 작성일: 2026-07-28
- 최종 갱신: 2026-08-01(배포 후 실사용 피드백으로 추가된 기능을 이 문서에 소급 반영)
- 상태: 사용자 승인 완료 (구현 계획 수립 대기) — 최초 MVP 기준 승인이며, 이후 변경은 배포 후 사용자 요청으로 진행됨(작업 분담 절 참고)

## 한 줄 설명

PDF 문서를 업로드하면 AI(OpenRouter 무료 모델)가 핵심 내용을 요약해 보여주는, 로그인 없는 단일 페이지 웹 도구.

## 배경

- 형제 프로젝트([`../7장 공감 다이어리 앱 Study_05_01`](../../../../7장%20공감%20다이어리%20앱%20Study_05_01))의 스택, 에이전트, `.env`를 재사용한다.
- 다만 이 앱은 형제 프로젝트와 달리 **로그인, DB 저장이 필요 없는 완전한 stateless 도구**다. `.env`는 형제 프로젝트와 동일한 파일을 재사용하지만, 실제로 이 앱이 쓰는 값은 `OPENROUTER_API_KEY` 하나뿐이다(`DATABASE_URL`, `AUTH_*`는 미사용).

## 범위

포함:
- PDF 업로드(드래그앤드롭 + 클릭 선택) → 서버에서 텍스트 추출 → OpenRouter 무료 모델로 요약 → 결과를 한 화면에 표시
- 한글 인터페이스, 반응형(모바일 포함)

제외(이번 범위 아님):
- 로그인/계정, 요약 히스토리 저장(DB)
- 긴 문서(20페이지/4MB 초과)에 대한 청킹(map-reduce) 처리 — 대신 명확한 제한 에러로 대응

배포 후 변경(최초 MVP 시점에는 "제외"였으나 이후 추가됨):
- 요약 결과 자체(summary/points 내용)는 여전히 완성된 형태로 한 번에 표시한다(토큰 단위 스트리밍 아님). 다만 어떤 무료 모델을 시도, 실패했는지에 대한 진행 상황은 SSE로 실시간 스트리밍한다.

## 아키텍처

- **프레임워크**: Next.js App Router, Vercel 배포 (형제 프로젝트와 동일 스택)
- **인증/DB 없음**: 완전한 stateless 도구. 업로드 → 처리 → 결과 표시가 여러 번의 요청-응답으로 끝난다(아래 API 참고). 새로고침하면 결과는 유실된다(의도된 동작).
- **페이지 구조**: 단일 페이지(`/`)에서 상태 전환으로 전체 흐름을 표현
  - `idle`(업로드 대기) → `processing`(텍스트 추출 중 → 요약 생성 중) → `result`(결과 표시, 반복 요약 시 결과 누적) / `error`(에러 표시)
- **API**: 배포 후 텍스트 추출과 요약을 분리해 3개 엔드포인트로 구성한다(최초 설계의 단일 엔드포인트 `/api/summarize`에서 변경).
  - `POST /api/extract` — PDF 파일(multipart)을 받아 검증 → 텍스트 추출 → `{ text }` JSON 반환. 추출이 끝나는 즉시 클라이언트가 원문 텍스트를 먼저 보여줄 수 있도록 요약과 분리했다.
  - `POST /api/summarize` — 추출된 텍스트(JSON `{ text }`)를 받아 OpenRouter 무료 모델로 요약한다. 응답은 일반 JSON이 아니라 **SSE(Server-Sent Events) 스트림**으로, 어떤 모델을 시도 중인지(`trying`)·실패했는지(`failed`)를 실시간으로 보내고, 마지막에 최종 결과(`done`: summary/points/model) 또는 실패(`error`)를 보낸다.
  - `POST /api/resummarize` — 직전 요약(summary+points)을 받아 한 단계 더 압축한 요약을 만든다. `/api/summarize`와 동일하게 SSE로 진행 상황을 스트리밍한다. 반복 호출할 때마다 결과가 새 항목으로 누적된다(이전 결과를 덮어쓰지 않음).
  - 세 엔드포인트 모두 세션/상태를 유지하지 않는다.

## 컴포넌트 구조

**프런트엔드** (`app/`, `components/`)
- `app/page.tsx` — 단일 페이지, 4가지 상태(idle/processing/result/error) 관리. 요약 결과는 배열로 관리해 "반복 요약하기" 결과가 누적되도록 한다.
- `components/UploadDropzone.tsx` — 드래그앤드롭 업로드 (파일 선택 클릭으로도 대체 가능)
- `components/PdfThumbnail.tsx` — 배포 후 추가. `pdfjs-dist`로 브라우저에서 PDF 첫 페이지를 즉시 캔버스에 렌더링한다(서버 왕복 없음, 서버사이드 CJK 폰트 이슈를 애초에 회피).
- `components/ExtractedText.tsx` — 배포 후 추가. `/api/extract` 응답으로 받은 원문 텍스트를 요약보다 먼저 스크롤 가능한 박스로 표시한다.
- `components/SummaryResult.tsx` — 요약 결과 표시. 여러 개의 요약(최초 요약 + 반복 요약)을 순서대로 쌓아서 보여주고, 각 결과 아래에 사용된/실패한 모델 정보를 표시한다. "다른 PDF 요약하기", "반복 요약하기" 버튼을 포함한다.
- 로딩 상태 표시 — "텍스트 추출 중...", "요약 생성 중 — {모델명} 시도 중"(실시간), 실패한 모델 목록
- 에러 메시지 컴포넌트 — 원인별 한글 문구. "다시 시도"(같은 파일로 재시도)와 "다른 파일 선택"(초기화)을 분리 제공한다(배포 후 개선 — 최초 버전은 실패 시 무조건 초기화였음).
- `lib/sse.ts` — 배포 후 추가. `/api/summarize`, `/api/resummarize`의 SSE 응답을 파싱하는 클라이언트 헬퍼.

**백엔드** (`app/api/`, `lib/`)
- `app/api/extract/route.ts` — 배포 후 추가. PDF 업로드 수신 → 검증(형식/용량/페이지) → 텍스트 추출 → `{ text }` JSON 응답.
- `app/api/summarize/route.ts` — 추출된 텍스트(JSON)를 받아 요약. SSE 스트림으로 모델 시도/실패/완료 이벤트를 전송한다(최초 설계에서는 PDF 업로드를 직접 받아 추출+요약을 한 번에 처리하는 단일 라우트였음).
- `app/api/resummarize/route.ts` — 배포 후 추가. 직전 요약을 받아 한 단계 더 압축. 마찬가지로 SSE 스트림.
- 세 라우트 모두 `export const maxDuration = 60` 설정(형제 프로젝트와 동일 패턴).
- `lib/pdf/extract.ts` — PDF 텍스트 추출. `unpdf` 채택(최종 확정). 한글(CJK) PDF 추출을 위해 `pdfjs-dist`를 실제 의존성으로 추가하고, `next.config.ts`의 `outputFileTracingIncludes`로 cmap 리소스를 서버리스 함수 번들에 강제 포함시켰다(배포 후 발견된 문제, 수정 완료).
- `lib/ai/openrouter.ts` — OpenRouter 연동. **무료 모델(`:free`) 순차 폴백 체인** 패턴. 배포 후 모델 시도/실패를 실시간으로 알려주는 콜백(`FallbackEventHandler`)을 추가했다.
- `lib/ai/summarize.ts` — 요약 생성 로직. 배포 후 다음과 같이 확장됨:
  - 최초 요약(`summarizeText`)과 반복 요약(`resummarizeText`)을 별도 함수, 별도 프롬프트로 분리했다. 반복 요약 프롬프트는 "같은 표현으로 바꿔 쓰지 말고 실제로 압축하라"고 명시하고, 최소 포인트 개수도 더 낮게(2개) 잡아 반복할수록 실제로 짧아지도록 한다.
  - 요약 분량은 고정된 "포인트 3~5개"가 아니라, **원문(또는 직전 요약) 글자 수의 약 25%**를 목표로 매 호출마다 동적으로 계산해 프롬프트에 명시한다. 일부 무료 모델이 목표 글자 수를 보면 계산 과정을 장황하게 출력하다 토큰 한도를 소진하는 경향이 있어, "계산 과정 없이 JSON만 출력"하도록 명시하고 토큰 한도도 목표 분량에 비례해 넉넉히 잡는다.

**환경변수**
- `OPENROUTER_API_KEY` — 이 앱에서 실제로 사용하는 유일한 값. 현재 폴더의 `.env`(형제 프로젝트와 동일 파일)에서 로드.
- `DATABASE_URL`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_SECRET` — `.env`에는 존재하지만 이 앱에서는 사용하지 않음.

## 업로드 제한

- 최대 **4MB**, 최대 **20페이지**
- 클라이언트에서 1차 검증(UX용, 즉시 피드백)하지만 **서버가 최종 권위**를 가지고 재검증한다.

## 데이터 흐름

1. 사용자가 PDF를 드래그앤드롭하거나 클릭으로 선택한다.
2. 프런트엔드가 파일 형식(PDF 여부), 용량을 1차 검증한 뒤, `PdfThumbnail`이 브라우저에서 즉시 첫 페이지를 렌더링해 보여주고, `processing` 상태로 전환한다.
3. 프런트엔드가 `multipart/form-data`로 `/api/extract`에 전송한다. 백엔드가 형식, 용량, 페이지 수를 재검증하고 텍스트를 추출해 `{ text }`를 반환한다.
4. 추출된 텍스트를 받는 즉시 화면에 먼저 표시한다("텍스트 추출 중..." → 텍스트 표시로 전환).
5. 프런트엔드가 추출된 텍스트를 JSON으로 `/api/summarize`에 전송한다. 백엔드가 OpenRouter 무료 모델 폴백 체인을 순차 시도하며, 각 모델의 시도/실패를 SSE로 실시간 전송한다("요약 생성 중 — {모델} 시도 중" 표시).
6. 모든 모델이 실패하면 SSE `error` 이벤트로 실패를 알린다. 하나라도 성공하면 `done` 이벤트로 구조화된 요약(summary/points/사용된 model)을 보낸다.
7. 프런트엔드가 `result` 상태로 전환하고 요약, 사용된/실패한 모델 정보를 표시한다. 실패 시 `error` 상태로 전환하며, "다시 시도"(같은 파일로 3~6단계 재실행) 또는 "다른 파일 선택"(초기화) 중 선택할 수 있다.
8. 사용자가 "반복 요약하기"를 누르면 직전 요약(summary+points)을 `/api/resummarize`에 전송한다. 동일하게 SSE로 진행 상황을 스트리밍하며, 성공 시 새 요약이 기존 결과 아래에 **추가**된다(덮어쓰지 않음). 매 반복마다 직전 입력의 약 25%로 더 압축된다.
9. "다른 PDF 요약하기"를 누르면 모든 상태(파일, 텍스트, 요약 결과)를 초기화하고 1단계로 돌아간다.

## 에러 처리

| 상황 | 발생 위치 | 처리 |
|---|---|---|
| PDF가 아닌 파일 | `/api/extract` | 400 JSON, "PDF 파일만 업로드할 수 있습니다." |
| 4MB/20페이지 초과 | `/api/extract` | 400 JSON, "문서가 너무 큽니다(최대 4MB, 20페이지)." |
| 텍스트 추출 불가(스캔 이미지 PDF 등 텍스트 레이어 없음) | `/api/extract` | 400 JSON, "이 PDF에서 텍스트를 추출할 수 없습니다." |
| OpenRouter 무료 모델 실패/429 | `/api/summarize`, `/api/resummarize` | 폴백 체인으로 순차 재시도(SSE로 각 시도/실패를 실시간 전송) → 모두 실패 시 SSE `error` 이벤트, "요약 생성에 실패했습니다. 잠시 후 다시 시도해 주세요."(재요약은 "재요약에 실패했습니다...") |
| 처리 시간 초과(Vercel `maxDuration=60`, 세 엔드포인트에 각각 독립 적용) | 전체 | 타임아웃 에러 메시지 표시 |

`/api/extract`는 검증 실패 시 일반 JSON 에러 응답(상태 코드 400)을 쓰지만, `/api/summarize`·`/api/resummarize`는 응답 자체가 SSE 스트림이므로 실패도 스트림 안의 `error` 이벤트로 전달된다(이 경우 HTTP 상태 코드는 200으로 유지됨).

## 테스트 범위 (qa-engineer, 최초 MVP 기준)

- 정상 경로: 일반 텍스트 PDF 업로드 → 구조화된 요약 성공적으로 표시
- 엣지케이스: 빈 PDF, 스캔 이미지(텍스트 없는) PDF, 페이지/용량 초과 PDF, PDF가 아닌 파일(.txt, .jpg 등), 한 문장짜리 초단문 PDF
- 무료 모델 레이트리밋/실패 상황에서 폴백 동작 확인
- UI: 드래그앤드롭 동작, 클릭 업로드 대체 경로, 로딩 상태, 에러 메시지 정확성, 결과 가독성(모바일 포함 반응형)
- 발견된 문제는 완전히 해결될 때까지 반복 수정한다(사용자 요청사항).

배포 후 추가된 기능들은 별도 qa-engineer 서브에이전트 없이, Claude Code가 실제 브라우저(모킹 및 실제 OpenRouter API 호출)로 직접 검증했다: 썸네일/추출 텍스트 표시 순서, 재시도 시 파일 유지, 반복 요약 결과 누적과 실제 압축 효과, SSE 모델 진행 상황 표시, 25% 분량 목표의 실동작. 정식 QA 리포트(`docs/qa-report-pdf-summary.md`)는 최초 MVP 범위만 다루며, 배포 후 기능에 대한 별도 QA 리포트는 작성되지 않았다.

## 작업 분담 (사용자 지정, 최초 MVP 기준)

1. **product-manager** — 이 설계를 바탕으로 상세 PRD, 기능 명세 작성
2. **backend-developer** — PDF 업로드, 텍스트 추출 기능 구현
3. **ai-integration-specialist** — OpenRouter 연동, 추출 텍스트 요약 기능 구현 (무료 모델, `.env`의 `OPENROUTER_API_KEY` 사용)
4. **frontend-developer** — 드래그앤드롭 업로드 UI + 요약 결과를 깔끔하게 보여주는 한글 인터페이스 구현
5. **qa-engineer** — 다양한 상황에서 테스트, 문제 발견 시 완전히 해결될 때까지 수정

최초 8개 태스크(위 5개 역할)는 `subagent-driven-development`로 진행됐다. 배포 후 추가된 기능들("배포 후 추가된 기능" 절 참고)은 별도 서브에이전트 디스패치 없이, 사용자의 실사용 피드백을 받아 Claude Code가 직접 구현, 검증(`tsc`/`eslint`/`build` + 브라우저 테스트), 배포까지 진행했다.

## 배포 후 추가된 기능 (MVP 이후, 이 문서에 소급 반영)

- PDF 첫 페이지 클라이언트 썸네일 표시
- 텍스트 추출/요약 API 분리(`/api/extract` 신설), 추출 텍스트를 요약보다 먼저 표시
- 요약 실패 시 파일 재선택 없이 같은 파일로 재시도
- "반복 요약하기": 직전 요약을 더 압축하는 별도 프롬프트, 결과 누적 표시(덮어쓰지 않음)
- 요약 분량을 원문(또는 직전 요약) 글자 수 대비 약 25%로 목표화
- AI 모델 시도/성공/실패를 SSE로 실시간 표시 + 결과에 영구 기록
