# PDF 요약 앱 — PRD (제품 요구사항 정의서)

- 작성일: 2026-07-28
- 작성자: product-manager (서브에이전트)
- 상태: 설계 문서([`docs/superpowers/specs/2026-07-28-pdf-summary-app-design.md`](superpowers/specs/2026-07-28-pdf-summary-app-design.md)) 승인 완료 기준으로 작성. 본 PRD는 그 설계의 기술, 범위 결정을 그대로 반영하며 뒤집지 않는다.

## 1. 한 줄 설명 / 배경

**한 줄 설명**: PDF 문서를 업로드하면 AI(OpenRouter 무료 모델)가 핵심 내용을 요약해 보여주는, 로그인 없는 단일 페이지 웹 도구.

**배경**:
- 형제 프로젝트인 [`../7장 공감 다이어리 앱 Study_05_01`](../../7장%20공감%20다이어리%20앱%20Study_05_01)의 스택(Next.js App Router + Vercel), 서브에이전트 구성, `.env` 파일을 재사용한다.
- 다만 이 앱은 형제 프로젝트와 성격이 다르다. 로그인이나 데이터 저장이 필요한 서비스가 아니라, **업로드 → 요약 → 결과 확인이 한 번의 요청-응답으로 끝나는 완전한 stateless 도구**다. 새로고침하면 결과는 사라지며, 이는 의도된 동작이다.
- `.env`는 형제 프로젝트와 동일한 파일을 재사용하지만, 이 앱이 실제로 쓰는 값은 `OPENROUTER_API_KEY` 하나뿐이다. `DATABASE_URL`, `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`, `AUTH_SECRET`은 파일에 존재해도 이 앱에서는 사용하지 않는다.
- 사용 목적: PDF 원문을 처음부터 끝까지 읽지 않고도, 몇 초~몇십 초 안에 핵심 내용(한 줄 요약 + 주요 포인트)을 파악할 수 있게 한다.

## 2. 목표와 성공 기준

### 목표 (Goals)

- **G1.** 사용자가 계정 없이 PDF를 업로드하기만 하면, 별도 조작 없이 핵심 내용을 빠르게 파악할 수 있게 한다.
- **G2.** OpenRouter 무료 모델만으로 안정적인 요약 품질과 가용성(폴백 체인)을 확보해 운영 비용 없이 서비스한다.
- **G3.** 인증, DB, 세션 없는 단순한 아키텍처를 유지해 구현, 운영 부담을 최소화한다.

### 비목표 (Non-goals)

- 요약 품질을 유료 모델 수준으로 끌어올리는 것은 목표가 아니다(무료 모델 한계 안에서 최선을 다한다).
- 대용량/초장문 문서를 완전히 지원하는 것은 목표가 아니다(4MB/20페이지 제한으로 범위를 명확히 좁힌다. 자세한 내용은 7절 Out of Scope 참고).

### 성공 기준 (Success Metrics)

| # | 기준 | 측정 방법 |
|---|---|---|
| SC1 | 정상 PDF(텍스트 레이어 있음, 4MB/20페이지 이내) 업로드 시, 업로드 시작부터 요약 결과 표시까지 **평균 30초 이내** | 개발/QA 단계에서 수동 스톱워치 측정(에이전트별 별도 계측 인프라는 두지 않음 — 9절 "가정, 제약, 리스크" 참고) |
| SC2 | 서버가 최종 권위로 검증하는 지원 파일 조건: **최대 4MB, 최대 20페이지**의 PDF | `app/api/summarize/route.ts`의 검증 로직 |
| SC3 | 모든 성공 응답은 **한 줄 요약 1개 + 주요 포인트 3~5개**의 구조화된 형식을 따른다 | API 응답 스키마(`{ summary: string; points: string[] }`) 및 QA 검증 |
| SC4 | 1순위 무료 모델이 실패해도 폴백 체인을 통해 다른 무료 모델로 재시도하며, 체인 전체가 실패하는 경우를 제외하면 요약 요청이 성공적으로 완료된다 | QA 시나리오(폴백 동작 확인) |
| SC5 | 6절에 정의된 모든 에러 상황에서, 사용자가 원인을 이해할 수 있는 한글 메시지를 즉시(추가 조작 없이) 확인할 수 있다 | QA 엣지케이스 검증 |
| SC6 | 처리 시간이 Vercel의 하드 타임아웃(`maxDuration=60`초)을 넘기지 않는다 | API 라우트 설정 및 QA 검증 |

## 3. 사용자 시나리오

이 앱은 로그인이 없으므로 별도의 사용자 세그먼트를 구분하지 않는다. "PDF 문서의 핵심을 빠르게 파악하고 싶은 모든 방문자"가 대상 사용자다.

앱은 단일 페이지(`/`)에서 4가지 상태(`idle` → `processing` → `result` / `error`)로 흐름을 표현한다.

### 시나리오 A — 정상 경로 (Happy Path)

1. 사용자가 `/`에 접속한다. 화면은 `idle` 상태로, 업로드 영역(드래그앤드롭 + 클릭 선택)이 보인다.
2. 사용자가 PDF 파일을 드래그해서 놓거나, 클릭해 파일 선택 창에서 PDF를 고른다.
3. 프런트엔드가 파일 형식(PDF 여부)과 용량을 1차 검증(즉시 피드백용)한 뒤, 통과하면 `processing` 상태로 전환하고 "요약 생성 중..." 을 표시하며 파일을 `/api/summarize`로 전송한다.
4. 서버가 형식, 용량, 페이지 수를 재검증(최종 권위)하고, 통과하면 PDF에서 텍스트를 추출한 뒤 OpenRouter 무료 모델에 요약을 요청한다.
5. 서버가 구조화된 요약(한 줄 요약 + 포인트 3~5개)을 JSON으로 응답한다.
6. 프런트엔드가 `result` 상태로 전환하고, 한 줄 요약과 포인트 목록을 화면에 표시한다.
7. 사용자는 "다른 PDF 요약하기" 버튼으로 언제든 `idle` 상태로 되돌아가 새 문서를 업로드할 수 있다.

### 시나리오 B — 실패 경로 (Error Path)

1~3번은 시나리오 A와 동일하되, 다음 중 하나가 발생하면 실패로 이어진다:
   - 업로드한 파일이 PDF가 아님
   - 파일이 4MB 또는 20페이지 제한을 초과함
   - PDF에서 텍스트를 추출할 수 없음(스캔 이미지 PDF 등 텍스트 레이어 없음)
   - OpenRouter 무료 모델 폴백 체인이 모두 실패함
   - 처리 시간이 60초를 초과함(타임아웃)
2. 프런트엔드(또는 서버 응답)가 `error` 상태로 전환하고, 원인에 맞는 한글 에러 메시지(6절 표 참고)를 표시한다.
3. 사용자는 "다시 시도" 버튼으로 `idle` 상태로 돌아가 다른 파일을 업로드하거나 같은 파일을 재시도할 수 있다.

## 4. 기능 요구사항

모든 기능은 이번 릴리스(MVP)의 필수 범위이며 우선순위는 전부 **P0(Must)** 다 — 이 앱은 범위가 이미 최소화되어 있어 P1/P2로 미룰 기능이 없다.

| # | 기능 | 설명 | 수용 기준(Acceptance Criteria) |
|---|---|---|---|
| F1 | PDF 업로드 (드래그앤드롭) | 사용자가 파일을 업로드 영역에 끌어다 놓아 업로드할 수 있다 | 드롭존에 파일을 드래그하면 시각적 피드백(hover 스타일)이 나타나고, 드롭 시 파일이 선택된다 |
| F2 | PDF 업로드 (클릭 선택) | 드래그앤드롭을 쓸 수 없는 환경(모바일, 키보드 사용자 등)을 위해 클릭 시 파일 선택 창이 열리는 대체 경로를 제공한다 | 업로드 영역 클릭 또는 키보드(Enter/Space)로 파일 선택 다이얼로그가 열리고, PDF 선택 시 동일하게 처리된다 |
| F3 | 클라이언트 1차 검증 | 서버 전송 전 파일 형식(PDF 여부), 용량을 즉시 검사해 사용자에게 빠른 피드백을 준다 | PDF가 아니거나 4MB를 초과하면 서버 요청 없이 즉시 `error` 상태로 전환되고 해당 메시지가 표시된다 |
| F4 | 서버 텍스트 추출 | 업로드된 PDF에서 본문 텍스트와 페이지 수를 추출한다 | 텍스트 레이어가 있는 PDF는 텍스트와 정확한 페이지 수가 추출된다. 텍스트 레이어가 없는 PDF(스캔 이미지 등)는 빈 텍스트로 판정되어 에러 처리된다 |
| F5 | 서버 최종 검증 | 형식, 용량, 페이지 수를 서버에서 다시 검증한다(클라이언트 검증은 우회 가능하므로 서버가 최종 권위) | 클라이언트 검증을 우회해 직접 API를 호출해도, 서버가 동일한 규칙(4MB/20페이지/PDF 형식)으로 거부한다 |
| F6 | AI 요약 (구조화) | 추출된 텍스트를 OpenRouter 무료 모델에 전달해 "한 줄 요약 + 포인트 3~5개" 형식의 구조화된 요약을 생성한다 | 성공 응답은 항상 `summary`(비어있지 않은 한 문장)와 `points`(3~5개 배열) 필드를 포함한다 |
| F7 | 무료 모델 폴백 체인 | 1순위 무료 모델이 실패(429/5xx/타임아웃/응답 파싱 실패)하면 다음 무료 모델로 순차 재시도한다 | 1순위 모델 실패 시에도 폴백 체인의 다른 모델이 성공하면 사용자는 정상적으로 결과를 받는다. 모든 모델이 실패해야만 에러가 노출된다 |
| F8 | 결과 표시 | 요약 결과(한 줄 요약 + 포인트 목록)를 한 화면에 표시한다 | 요약 문장과 포인트 목록(불릿)이 가독성 있게 보이며, 모바일 화면에서도 잘리거나 가로 스크롤이 생기지 않는다 |
| F9 | 에러 처리 | 6절에 정의된 각 실패 상황에 대해 원인별 한글 메시지를 표시한다 | 각 에러 상황에서 표시되는 메시지가 6절의 표와 정확히 일치한다 |
| F10 | 처리 중 상태 표시 | 서버 처리 동안 "요약 생성 중..." 등 로딩 상태를 보여준다(스트리밍 아님, 완료 후 일괄 표시) | 요청 전송 시점부터 응답 수신까지 `processing` 상태가 유지되고, 그동안 업로드 영역은 비활성화되거나 숨겨진다 |
| F11 | 재시작 흐름 | 결과/에러 화면에서 다시 초기 업로드 상태로 돌아갈 수 있다 | "다른 PDF 요약하기"(결과 화면)/"다시 시도"(에러 화면) 버튼 클릭 시 `idle` 상태로 복귀하고 이전 결과/에러는 초기화된다 |

## 5. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| **업로드 제한** | 최대 파일 크기 **4MB**, 최대 **20페이지**. 클라이언트에서 1차 검증(즉시 피드백용)하되, **서버가 최종 권위**를 가지고 재검증한다. |
| **처리 시간** | API 라우트(`app/api/summarize/route.ts`)는 Vercel의 `export const maxDuration = 60`(초) 설정을 따른다. 목표 응답 시간은 평균 30초 이내(2절 SC1). |
| **모델 비용** | OpenRouter의 **무료 모델(`:free`)만** 사용한다. 유료 모델은 사용하지 않는다(운영 비용 0원 유지). |
| **인증/데이터 저장** | 로그인, 계정, DB 없음. 완전한 stateless 구조 — 업로드부터 결과 표시까지 한 번의 요청-응답으로 끝나며, 요약 결과는 서버에 저장되지 않고 새로고침 시 유실된다(의도된 동작). |
| **API 구조** | 단일 엔드포인트 `POST /api/summarize`. `multipart/form-data`의 `file` 필드로 PDF를 받아, 검증 → 추출 → 요약을 한 번에 처리한 뒤 결과(JSON)를 반환한다. 세션/상태를 유지하지 않는다. |
| **언어/지역화** | 모든 UI 텍스트와 에러 메시지는 한국어로 제공한다. |
| **반응형** | 데스크톱과 모바일 모두에서 사용 가능해야 하며, 업로드 영역과 결과 화면이 좁은 화면(약 375px)에서도 잘리거나 가로 스크롤을 유발하지 않아야 한다. |
| **접근성** | 업로드는 마우스 드래그앤드롭뿐 아니라 클릭과 키보드(Tab 포커스 + Enter/Space)로도 동일하게 수행할 수 있어야 한다. |
| **보안** | `OPENROUTER_API_KEY`는 환경변수로만 다루며 로그, 응답, 커밋에 절대 노출하지 않는다. |
| **관측성** | 별도의 로그 저장소나 모니터링 인프라는 두지 않는다(stateless 원칙과 일관). 필요 시 개발 중 디버그 로그(`AI_DEBUG` 등)로만 폴백 동작을 확인한다. |

## 6. 에러 케이스 표

아래 표는 설계 문서의 에러 처리 표를 그대로 인용한 것으로, 값, 메시지를 변경하지 않는다.

| 상황 | 처리 |
|---|---|
| PDF가 아닌 파일 | 400, "PDF 파일만 업로드할 수 있습니다." |
| 4MB/20페이지 초과 | 400, "문서가 너무 큽니다(최대 4MB, 20페이지)." |
| 텍스트 추출 불가(스캔 이미지 PDF 등 텍스트 레이어 없음) | 400, "이 PDF에서 텍스트를 추출할 수 없습니다." |
| OpenRouter 무료 모델 실패/429 | 폴백 체인으로 순차 재시도 → 그래도 실패 시 502, "요약 생성에 실패했습니다. 잠시 후 다시 시도해 주세요." |
| 처리 시간 초과(Vercel `maxDuration=60`) | 타임아웃 에러 메시지 표시 |

## 7. Out of Scope (이번 범위 아님)

다음 항목들은 이번 릴리스(MVP)에서 의도적으로 제외한다. 설계 문서에서 이미 결정된 제외 범위이며, 이번 PRD 작업 중 임의로 추가한 항목이 없다.

- **로그인/계정**: 인증 시스템, 사용자 계정, 소셜 로그인 등 일체 없음. `.env`에 `AUTH_*` 값이 존재해도 이 앱에서는 사용하지 않는다.
- **요약 히스토리 저장(DB)**: 과거 요약 결과를 저장, 조회하는 기능 없음. `DATABASE_URL`이 `.env`에 존재해도 이 앱에서는 사용하지 않는다. 새로고침 시 결과는 유실된다(의도된 동작).
- **스트리밍 요약 표시**: 요약이 생성되는 과정을 실시간으로 스트리밍해 보여주지 않는다. 처리 완료 후 결과를 한 번에 표시한다.
- **긴 문서 청킹(map-reduce) 처리**: 20페이지/4MB를 초과하는 문서를 여러 조각으로 나눠 처리하는 기능은 없다. 대신 명확한 제한 초과 에러(6절)로 대응한다.

### 향후 고려 (이번 범위와 무관, 참고용)

위 Out of Scope 항목들은 제품 설계상 확정된 제외 범위이며, 이 PRD가 향후 재검토를 제안하는 것은 아니다. 별도의 신규 요구가 없는 한 이 문서의 유효 기간 동안 범위 확장을 고려하지 않는다.

## 8. 작업 분담

설계 문서에서 사용자가 지정한 순서와 역할을 그대로 따른다.

| 순서 | 역할(서브에이전트) | 담당 범위 |
|---|---|---|
| 1 | **product-manager** | 본 PRD 및 기능 명세 작성 (완료) |
| 2 | **backend-developer** | Next.js 프로젝트 스캐폴딩, PDF 업로드 수신, 검증, PDF 텍스트 추출(`lib/pdf/extract.ts`), `/api/summarize` 라우트 골격 구현 |
| 3 | **ai-integration-specialist** | OpenRouter 연동(`lib/ai/openrouter.ts`), 추출된 텍스트를 구조화된 요약(한 줄 요약 + 포인트)으로 변환하는 로직(`lib/ai/summarize.ts`) 구현, 무료 모델 폴백 체인 적용 |
| 4 | **frontend-developer** | 드래그앤드롭 + 클릭 업로드 UI, 4가지 페이지 상태(idle/processing/result/error) 관리, 결과 표시 컴포넌트, 반응형, 접근성 다듬기 |
| 5 | **qa-engineer** | 정상/엣지케이스(빈 PDF, 스캔 이미지 PDF, 용량/페이지 초과, PDF 아닌 파일, 초단문 PDF) 테스트, 무료 모델 폴백 동작 확인, 발견된 문제는 완전히 해결될 때까지 반복 수정 |

각 역할은 이전 역할의 산출물(인터페이스)을 그대로 소비한다: backend-developer의 텍스트 추출 결과 → ai-integration-specialist의 요약 함수 입력 → frontend-developer의 API 호출 대상 → qa-engineer의 전체 검증 대상.

## 9. 가정, 제약, 리스크 (Assumptions & Risks)

**가정**:
- 이 앱은 별도 분석/로그 저장소가 없으므로, 2절의 SC1(평균 처리 시간)과 SC4(폴백 성공률) 같은 지표는 프로덕션에서 자동 계측되지 않는다. 개발, QA 단계의 수동 측정으로 목표 달성 여부를 확인한다.
- OpenRouter의 무료 모델 목록은 수시로 바뀔 수 있다. 설계 문서에 언급된 특정 모델명은 구현 착수 시점에 ai-integration-specialist가 최신 상태를 재확인해 결정한다(본 PRD는 "무료 모델만 사용"이라는 정책만 확정하며, 특정 모델명을 확정하지 않는다).
- `unpdf`를 포함한 PDF 파싱 라이브러리의 최종 선택은 backend-developer 착수 시 확정된다(설계 문서 "미해결/후속 확인 사항" 참고).

**제약**:
- Vercel 서버리스 함수의 `maxDuration=60`초를 넘는 처리는 불가능하며, 이는 처리 시간 목표(SC1)의 상한선이다.
- 무료 모델만 사용하므로 요약 품질과 응답 속도는 유료 모델 대비 제한적일 수 있다.

**리스크**:
- 무료 모델의 레이트리밋(429)이 동시에 여러 모델에서 발생하면 폴백 체인 전체가 실패해 사용자에게 502 에러가 노출될 수 있다. 완화책은 F7(폴백 체인)이지만 완전히 제거되지는 않는 리스크다.
- 스캔 이미지 기반 PDF(OCR 텍스트 레이어 없음)는 이 앱의 설계상 지원 범위 밖이며, 사용자에게는 "텍스트 추출 불가" 에러로만 안내된다(OCR 미지원은 확정된 설계 결정).
